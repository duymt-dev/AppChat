01 — Product Overview

Tổng quan sản phẩm & tầm nhìn

AppChat là nền tảng Nền tảng AI Agents vận hành Doanh nghiệp Một Người dạng SaaS B2B — hợp nhất 19 kênh nhắn tin về một hộp thư, vận hành bởi con người + AI Agent, phục vụ doanh nghiệp dịch vụ có khách quay lại nhiều lần.

Hợp nhất đa kênh
19 kênh social/nhắn tin → một hộp thư duy nhất, AI co-pilot hỗ trợ trả lời.
Vận hành bằng AI
AI Agent tự tư vấn, phân luồng, tạo lead/ticket/lịch hẹn; trợ lý nội bộ Omi ra lệnh tạo agent/workflow/chiến dịch/báo cáo.
CRM360 + Loyalty
Hồ sơ 360°, pipeline Lead→Won, báo giá/hợp đồng/đơn hàng, hạng thành viên & tích điểm.
Tự động hoá
Workflow visual theo ngành, follow-up theo giai đoạn, chiến dịch marketing đa kênh.
Đo lường & BI
10 báo cáo gom 5 nhóm, "1 con số 1 nguồn", token metering & ROI.
Đa workspace
1 khách hàng dùng đồng thời workspace Cá nhân + Team + Doanh nghiệp.
★
Định vị: "respond.io + CRM + AI Agent" thiết kế riêng cho ngành dịch vụ Việt Nam — Zalo-first, tiếng Việt mặc định, tính phí theo token AI.

08 — Multi-tenancy

Đa tenant & workspace

Hình 3. 1 user/đội nhóm dùng đồng thời nhiều workspace; mua thêm workspace = thêm tài khoản.

Chiến lược: Shared DB + shared schema + Row-Level Security — mọi bảng có workspace_id, policy workspace_id = current_setting('app.tenant'). Billing/seats/token-budget tách theo từng workspace; workspace switcher trong Profile.

09 — Channel & Realtime

Channel Gateway & Realtime

Channel Gateway

  • Adapter chuẩn hoá 19 kênh về mô hình message chung.
  • Inbound: webhook verify → enqueue → parse idempotent.
  • Outbound: outbox pattern + retry/back-off + rate-limit per channel.
  • OAuth token store mã hoá, auto-refresh.

Realtime & Events

  • WebSocket room theo workspace + conversation.
  • Presence/typing/seen qua Redis pub/sub.
  • Domain events: message.received, quote.won, order.completed, ai.token_used…

15 — API Contract (Dev)

API Contract (OpenAPI 3.1) — cho Dev

API-first, versioned /v1, cursor pagination, mọi request mang Authorization: Bearer + X-Workspace-Id, POST gửi tin/tạo đơn kèm Idempotency-Key.

# Auth POST /v1/auth/otp/request { phone } → { otp_token } POST /v1/auth/otp/verify { otp_token, code } → { jwt, refresh } POST /v1/auth/social { provider, id_token } → { jwt } # Workspace (đa tenant) GET /v1/workspaces → [{id,name,plan,role}] POST /v1/workspaces/switch { workspace_id } → { ok } # Conversation / Message GET /v1/conversations?status=open&channel=zalo&cursor=… POST /v1/conversations/{id}/messages (Idempotency-Key) { type, body } POST /v1/conversations/{id}/assign { assignee_id } POST /v1/conversations/{id}/tags { tag_ids[] } # CRM · Sales flow GET /v1/contacts/{id} → hồ sơ 360° POST /v1/quotes { contact_id, items[] } · POST /v1/quotes/{id}/win POST /v1/orders/{id}/complete → emit order.completed (Loyalty +điểm) # AI · Workflow · Billing POST /v1/ai-agents { persona, model, actions, routing } POST /v1/workflows { name, nodes } · POST /v1/workflows/{id}/run GET /v1/billing/token-usage?from=…&to=… POST /v1/billing/topup { pack: A|B|C, method: qr|bank|gateway } # Webhook POST /webhooks/channels/{provider} (verify chữ ký) POST {customer_url} X-Signature: HMAC event=order.completed
Mã lỗiÝ nghĩaMã lỗiÝ nghĩa
401Chưa xác thực409Idempotency trùng / xung đột
403Sai workspace/quyền422Dữ liệu không hợp lệ
404Không thấy tài nguyên429Vượt rate-limit
◆
Chuẩn response: bọc { data, meta:{cursor,total}, error }. Mọi list trả meta.cursor cho phân trang. OpenAPI 3.1 là nguồn chân lý → sinh client SDK + mock server tự động.

Use-case tiêu biểu (định dạng chuẩn BA)

UC-01 · Tiếp nhận & trả lời hội thoại
Tiền đề: khách nhắn 1 trong 19 kênh. Luồng chính: webhook → tạo conversation → AI co-pilot gợi ý → agent gửi trả. Hậu điều kiện: message lưu, SLA đếm. Ngoại lệ: ngoài giờ → AI tự xử lý.
UC-02 · Chốt deal qua Sales flow
Luồng: Báo giá → khách đồng ý → "Chốt" → tạo Hợp đồng → sinh Đơn hàng → pipeline stage = Won → order.completed → Loyalty cộng điểm.
UC-03 · Omi tạo chiến dịch
Luồng: user ra lệnh "soạn ZNS nhắc tái khám" → Omi đề xuất luồng → xác nhận/điều chỉnh/tái dùng → tạo workflow + campaign → ghi Nhật ký (Hoàn tác được).
UC-04 · Follow-up theo giai đoạn
Luồng: contact đổi stage → cadence sinh follow-up đúng nhịp → hiện trên Lịch → agent/AI thực hiện → ghi nhận kết quả.
UC-05 · Ticket + SLA escalation
Luồng: tạo ticket → gán theo tổ chức → SLA đếm → cảnh báo 80% → escalation → đóng. Quy tắc: đã duyệt chỉ tạm dừng/xoá.
UC-06 · Mua thêm token khi hết
Luồng: token hết (gói còn hạn) → popup → chọn gói A/B/C → thanh toán QR/chuyển khoản → nạp token → tiếp tục dùng AI.

Quy tắc nghiệp vụ (Business Rules) tiêu biểu

  • BR-01: Hạ gói không quy đổi token/thời gian còn lại; đổi gói tính lại theo gói mới.
  • BR-02: Chiến dịch đã duyệt chỉ được tạm dừng hoặc xoá, không sửa.
  • BR-03: Gói Cá nhân chỉ 1 user; muốn thêm user dùng chung phải nâng lên Doanh nghiệp.
  • BR-04: Tích điểm = sàn(tổng tiền đơn / 1.000); quy đổi 10 điểm = 1.000đ (cấu hình được).
  • BR-05: Omi không thực thi khi chưa có xác nhận rõ ràng của người dùng.
  • BR-06: Khi token vượt ngưỡng tạm ngừng (vd 5.000.000₫) → khoá AI đến khi thanh toán.

DevOps · CI/CD · Runbook

Pipeline CI/CD

# GitHub Actions push → lint + unit + contract test → SCA/SAST scan → build image (multi-stage) → push registry → deploy staging (Helm) → E2E smoke → approval → deploy prod (blue/green hoặc canary 10%→100%)

Môi trường & hạ tầng

  • dev / staging / prod tách hoàn toàn; IaC bằng Terraform; cấu hình Helm values.
  • Workers auto-scale (HPA) theo độ sâu hàng đợi Kafka.
  • Postgres primary + read replica, PgBouncer; backup PITR (RPO ≤5p).
