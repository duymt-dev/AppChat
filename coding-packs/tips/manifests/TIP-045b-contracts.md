# TIP045b implementation contracts — security and vertical-flow reliability

This annex is mandatory task scope, not optional advice. Existing source is evidence of missing behavior, not proof this plan is implemented. Preserve commerce, five system roles, D51 and native data/services. Implement bounded domain batches; kernel must not import business-domain components.

## A. Platform-first consistency, audit and ownership

### A1. Replace nested cross-DB transactions, not pretend they are atomic
- Current executor platform transaction nests tenant transaction, then writes tenant log/receipt separately. Introduce platform operation ledger with unique(workspace_id,actor_key,idempotency_key), action_id, canonical_input_hash, phase, result descriptor, effect references, lease/fence and timestamps. Raw secret inputs never persisted. Same key/different input409. Canonical intent and confirmation023b remain required before creating a business operation.
- Phases: prepared -> platform_applied -> tenant_applied -> complete, with explicit failed/compensation_required. Platform mutation/reservation, operation receipt and platform audit/effect intentions commit together FIRST. Tenant apply then commits business projection, approval consumption where applicable, action_log, outbox and unique operation receipt together. Final platform acknowledgement can be retried. No tenant writable transaction passed to the platform phase; handler adapters expose separated plan/apply methods. Read-only validation may occur before reservation, but authority and versions rechecked at the relevant commit.
- Every implemented db:platform handler enumerated in exact manifest gets adapter classification: platform-only mutation + tenant audit receipt, or quota reservation + tenant business effect (agent/channel creation). No opportunistic fallback to old nested transaction. Stub wallet.update_alerts remains unsupported until its owner039 implements the same protocol; test excludes registered NotImplemented fallback, not silent fake support.
- Platform-only actions return success only after durable platform effect and tenant receipt. Partial operation returns existing032b job_accepted with operation/job handle, not false success or a new mutation on retry. Recovery records phase/fence and replays missing phase only. Deterministic rejection can release quota reservation through a compensating platform operation; unknown external effect is not compensated/retried blindly. A failed tenant projection does not make a committed platform role change disappear.
- Authority changes update platform authz_epoch in the SAME transaction. Every action/read resolver checks active membership/current owner+epoch before using cached role/scope; Redis/outbox invalidation is acceleration, not security boundary. Missing tenant custom-role projection fails closed. Pending restrictive changes never grant old authority. Owner transfer and member.remove must revoke socket/AI/file access even if relay is down. Custom-role042 is a successor, not a prerequisite cycle.
- member.invite currently sends mail inside platform transaction. Move mail to durable encrypted effect payload, retaining token only encrypted with bounded TTL, receipt-bound and redacted; provider send after commit. Do not generate a replacement invitation on retry. Invite accept endpoint/service enters the same idempotent platform operation path, preserving authenticated matching email, expired/revoked token checks and seat quota lock. Undo of platform actions is a NEW conditional operation referencing original receipt, never PlatformDb writes from a tenant-only undo transaction. Recheck current authority, target membership and role version.
- Register consistency recovery/effects workers under ROLE=jobs; stable queue IDs, leases/fencing, bounded retries, explicit dead-letter/status and replay controls. Recovery completes recorded committed intent; it must not invent business repairs. Hourly reconciliation below is report-only and separate from operation recovery.
- Approval continuation is a durable pending receipt keyed by approval_id + operation_id + run_id, not APPROVAL_LOOP or `{executed:true}`. Extend032b accepted handle with operation-pending semantics distinct from a queued bulk-job acknowledgement. Keep run waiting_approval with explicit waiting_operation metadata; never resume model or mark final tool result while tenant apply is missing. Persist operation/approval binding before first platform mutation; recovery discovers that binding even if tenant DB was unavailable to record the pending marker. On tenant apply, consume approval and store canonical result in the same transaction; a uniquely keyed continuation outbox event wakes ROLE=ai. Recheck current commander/agent authority before projecting result or resuming; revoked actor gets terminal unavailable/handoff, not a rerun of committed effects. Run claim + continuation receipt +023c shared terminal finalizer make duplicate completion/restart idempotent. Existing executed_at without result resolves operation receipt or remains pending, never fabricated success. Kernel emits generic operation completion; AI consumer owns resume, avoiding kernel->AI imports.

### A2. Audit read/write and trace
- Platform operations/admin.* append platform_audit_log in their platform commit; tenant sensitive actions set audit flag and normal action_log in transaction. Use schema-aware redaction for input/result/before/after; no raw OTP, credential, prompt, message body or token URL. Do not recurse audit logging into itself. Internal effects reference operation+trace IDs, not sensitive payload.
- GET /v1/settings/audit and /v1/settings/ai-audit require audit.view/current membership. Add cursor/filter support (actor/action/status/time), bounded page50, deterministic created_at DESC,id DESC; keep no-parameter legacy array compatibility through DTO adapter while new paged UI uses explicit query mode. AI audit joins scoped run/step metadata only: task, actor, model, credit/token count, status, time, trace; full prompts or customer data need their own current resource authority and are not returned by these routes.
- Platform admin audit cannot be exposed as workspace audit across tenants. Audit readers use current field projection, not historical permission snapshots; raw secrets remain redacted even for Owner. All error/empty/loading/retry/filter states in real AuditSection; no mock-only success toast. Security events notify Owner through deduplicated outbox, with safe details; transfer notifies previous and new Owner. Session creation records new-device event using bounded hashed device identity, not raw fingerprint/PII in metrics.
- trace_id originates validated HTTP request ID or server-generated ID; carry into action log, ai_run, every queue producer, retry, outbox envelope and channel result. All current Queue/Worker construction sites are enumerated in manifest, plus new workers register with with-job-context. RequestContext.run scopes each job separately; malformed external trace IDs replaced, attempts preserve root trace. Scheduled tasks generate their own trace. No mutable global context leaking between tenants.

New workspace.request_transfer_otp and workspace.transfer_ownership use config risk, non-agent, current owner identity verified server-side from workspace.owner_user_id (permission does not authorize a delegated non-owner to transfer).

Bind OTP to workspace, old owner, target member, owner/authz epoch and operation; consume with platform transfer commit. No OTP/body in audit/model. ## B. HTTP/network/file boundary and metrics

- safeFetch only http/https, no userinfo/fragments/unsupported ports, normalize IPv4/IPv6 (including mapped forms); reject loopback/private/link-local/multicast/unspecified/metadata/reserved ranges on EVERY A/AAAA result and redirect. Pin vetted address to socket while preserving HTTPS SNI/hostname verification; do not validate DNS then call fetch which resolves again. Reject mixed public/private answers, redirect limit3, no credential forwarding to new origin; max10s and streamed decoded-byte cap10MB (KB may retain lower5MB). Abort oversized/chunked/compressed body before buffering. Test DNS rebinding, alternate numeric IPs and redirects with local fixture resolver, not Internet probes.
- KB ingest uses injected safeFetch. Zalo adapter's unrestricted default fetchFile is removed/fail-closed; ChannelsModule supplies attachment-fetcher. Signed own-file URL must match configured origin+exact route and valid binding; resolve authorized workspace/file via Storage directly, never a general localhost exemption. External media uses safeFetch with explicit approved media bound<=25MB. Keep channels package dependency direction: FileFetcher port exists, core provides implementation. Native local document sending must still work. Future connector/webhook user URL consumers must use this boundary; credential provider ports do not become arbitrary HTTP proxy.
- Upload guard applies at FilesService for every caller, not only multipart controller: bounded size, normalized name, purpose-specific mime/signature and container checks. Images10MB, documents25MB, DOCX templates10MB. Reject mismatched extension/mime, SVG/script masquerade, encrypted/macros/ZIP traversal/bomb and excessive expansion before extraction; OOXML XLSX/DOCX distinguish content types. CSV UTF8/text bounds and formula injection neutralization on export. MP4 checks ftyp/container bounds, not arbitrary four-byte match.030b document parser remains stricter domain guard; kernel does NOT import documents domain. Reuse lower-level bounded primitives through approved public boundaries only.
- Storage implements local or s3 by validated config; local remains default, never silently switch production data. S3-compatible endpoint/bucket/prefix credentials are server configuration, not model input. Use approved SDK dependency deviation DV019, least-privilege object operations and workspace-prefixed keys, private ACL, integrity SHA256, bounded streams/timeouts and stable object key retries. No presign bypass of file confirmation. Existing multipart DV003 stays compatible; S3 storage support does not claim presign UI implemented. Missing configured backend fails boot; errors redact endpoint credentials. Test native fake S3-compatible service or authorized staging bucket, not mock-only provider claim.
- Global limiter Redis atomic sliding window: reads600/min/user, actions120/min/user, public30/min/IP; retain stricter OTP5/min/email+20/hour/IP and widget limits. Tenant switching cannot reset per-user limit. Trust forwarded IP only from configured proxy; unknown routes no attacker-controlled metric labels.429 standard envelope+Retry-After; OPTIONS/health/metrics separate bounded policy. Redis unavailable: protected writes/auth/public-token operations fail503, do not silently disable limits; health stays observable.
- CORS exact app origins; widget origins validated per registered workspace widget config, not permissive wildcard with credentials. WebSocket Origin checks align with HTTP. Helmet/security headers include CSP compatible with current PDF/QR/iframe/embed behavior, frame restrictions and nosniff; do not break legitimate widget embedding with blanket deny. Browsers' absence of Origin is not an authentication substitute. Credentialed requests cannot use wildcard. No CSRF weakening of refresh cookie policy.
- prom-client/helmet approved Blueprint dependencies; install exact lockfile versions only in future build. Process-local metric registry, private127.0.0.1 worker listener per role configurable nonconflicting ports; API route authenticated internal token OR bound private listener, never public /metrics via reverse proxy. Metrics: HTTP duration/action result/job duration/queue depth/outbox lag/LLM latency tokens errors/credit charge/channel sends and aggregate account status/tenant pool clients/approval wait. Labels bounded route templates, action ID, queue family, provider/model from configured finite registry; no workspace/user/account/run IDs. Shutdown closes listener and clears collectors; duplicate module bootstrap does not double-register.

## D. Human takeover, one conversation run and background jobs
