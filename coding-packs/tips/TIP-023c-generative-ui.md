## Additional recovery and owned-task contracts

### Fenced recovery / approval / secret vault
- Request ledger unique(user_id,request_id) within tenant DB; input_hash includes session_id and canonical non-secret request. A reused request_id for another session returns409. No secret bytes in key/hash/log.
- Request ledger in ai-assistant.prisma owns execution_state (queued/running/waiting_external/waiting_approval/succeeded/failed/cancelled), lease_owner, lease_until, monotonically increasing fence and checkpoint_version. Do not silently change AiRun enum: map waiting_external to ledger and make runner/run.store consult it. Atomic reclaim of expired lease uses Clock; renew only owner+fence. Every event/checkpoint/finalizer/tool dispatch validates fence, including inside mutation transaction. Stale workers cannot append, dispatch new tools or finish; already-dispatched external effects reconcile by stable receipt, never blind retry.
- Recovery index(execution_state,lease_until,id) INCLUDE(run_id,fence), partial nonterminal; select bounded IDs before payload. Persist waiting checkpoint and expected node/attempt before release; early verified external receipt is retained and matched atomically. Cancellation is terminal; late QR/approval receipt never resurrects run.
- AiJobsModule registers registerResumeFinish('assistant',...) as well as registerResumeSpec. Normal turn processor and approval resume use ONE durable finalizer, unique on run_id+checkpoint_version+terminal event kind. Persist history/SSE terminal event transactionally once. Approval denial/revoke/cancel has explicit terminal/paused result, not silent spinner.
- Vault consume-once means ACK AFTER durable action receipt, not GETDEL before transaction. Claim encrypted value with lease bound actor/tenant/action/intent; rollback/precommit crash can reclaim same operation until TTL. Postcommit retry returns receipt without decrypting/repeating. Expired precommit vault returns re-entry-required and invalidates old intent, never success. Confirmation-token recovery uses same operation ledger rather than permanent failure because existing executor consumes token before DB transaction.

### Inbox compose/rewrite (REQ-C05c)
