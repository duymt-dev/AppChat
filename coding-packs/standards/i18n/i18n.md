# i18n — Nền đa ngôn ngữ

> Chốt V15 / D22. Phát hành `vi` + `en`. Registry khai sẵn 11 ngôn ngữ; thêm ngôn ngữ là việc dữ liệu, không sửa code.

## Quy tắc

1. **Không chuỗi hiển thị cứng** trong JSX / TSX, trong `message` hiển thị cho người dùng, email hay PDF.
   - Mọi chuỗi đi qua next-intl (`t('module.key')`), ICU MessageFormat.
   - Lint `eslint-plugin-i18next` bật mức error.
2. **Key theo module:** `apps/web/messages/<locale>/<module>.json`. `vi` là nguồn. `en` phải đủ key trước khi merge (`pnpm i18n:check`).
3. **Không nối chuỗi.** Dùng biến và plural của ICU: `{count, plural, one {# khách} other {# khách}}`.
4. **Định dạng qua helper** `fmt.money/date/number/relative` (`packages/shared`), theo locale + timezone workspace. Cấm `toLocaleString()` rải rác, cấm format tiền tay.
5. **Lỗi server trả `code`;** client dịch qua `errors.<CODE>`. `fields` cũng là mã lỗi.
6. **Nhãn từ registry** (action title, channel label, connector name, permission, vai trò hệ thống) là i18n key. Tên vai trò tuỳ biến do người dùng nhập thì giữ nguyên văn.
7. **Đổi ngôn ngữ đồng bộ:** next-intl + antd `ConfigProvider locale` + Ant Design X + dayjs.
   - Locale lấy theo thứ tự `user.locale` → `workspace.locale` → `Accept-Language` → `vi`.
   - Không đưa locale vào URL.
8. **Server render theo locale người nhận:** email, PDF báo giá / đề nghị thanh toán / hợp đồng, thông báo. Template ở `packages/shared/i18n/server/<locale>/`.
9. **AI:** prompt có bản theo locale (`*.vi.md`, `*.en.md`). Agent trả lời theo `contact.locale`. Không tự dịch dữ liệu doanh nghiệp nhập.
   - **Ngoại lệ D55 — Generative UI:** tiêu đề / diễn giải / nhãn trong cây giao diện do Trợ lý ghép là chữ LLM viết theo `user.locale`, không qua i18n key. Nhãn hệ thống (Xác nhận, Huỷ, Thử lại, Không có dữ liệu, trạng thái tải) và định dạng tiền / ngày / số vẫn qua i18n + `fmt` (`ai/generative-ui.md` §6).
10. **Bật ngôn ngữ mới** khi độ phủ ≥ 98% và đã kiểm UI độ dài chữ. Menu chỉ hiện ngôn ngữ `enabled`.
